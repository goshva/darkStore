## 3. Что найдено в коде сверх разбора

### Н-1. Неделя 5: «выходы 0%» — унаследованное значение, а не факт
В форме недели 5 есть `curatorAutonomy5`, `curatorKpi5`, `tmc5`, `lateness5`, `appeals5` — **и нет `exits5`**. `mergedForWeek` добирает отсутствующую метрику из данных недели 1.
Прогон `ds_audit.cjs`:
```
exits недели 5 = 0            (в данных недели 5 поля exits5 нет)
если поменять exits недели 1 на 95 -> exits недели 5 = 95   (неделя 5 не менялась)
```
**Следствие:** «провал выходов на неделе 5» из разбора — артефакт. Неделя 6 наследует выходы через тот же дефект (`753` ссылается на несуществующий `exits5`).

### Н-2. Присланный отчёт арифметически невоспроизводим
В сводке нет `orders_per_day`, `zones_count`, весов потерь, ставки по неделям и разложения потерь. Если восстановить объём заказов из прибыли по неделям (при заявленных чеке 1 050 ₽, марже 5%, ставке 100 ₽ и дефолтных весах):

| Неделя | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| Подразумеваемый Q, заказов/день | 4 801 | 4 576 | 2 526 | 1 396 | 5 219 | 2 644 |

Модель так не умеет: `Q = zonesCount × ordersPerZoneDay` берётся из калибровки недели 1 и по неделям не меняется. То есть либо отчёт собран другим состоянием/сборкой, либо числа правились руками. **Пока в отчёте нет входов модели, это невозможно даже проверить** — это и есть главный P0.

### Н-3. «Заполнена неделя» = есть любое поле
`profitForWeek(w)` возвращает расчёт, если в неделе есть хотя бы один ключ (`377`). Прогон:
```
неделя 2 = { dsName: 'Даркстор №7' }  -> profitForWeek(2) != null
Отчёт: "Последняя заполненная неделя: 3"  (в неделе 3 было только ФИО куратора)
```
**Следствие:** «Заполнено недель: 6 из 6» ничего не гарантирует; в таблицу прибыли попадают недели, где метрики целиком унаследованы или дефолтные.

### Н-4. Гейт куратора игнорирует калибровку
`index.html:1762` — жёстко `lastP.curatorMin >= 90`, хотя порог задаётся слайдером `curatorThreshold`. Прогон при пороге 60% и кураторе 70%:
```
- [НЕТ] куратор ≥ 90%: 70%      <- должно быть [OK]
```

### Н-5. Часть плана ИИ молча теряется
- `tmc_target_pct` не применяется нигде (`1590`: `if (key === 'tmc_target_pct') return;`).
- `zones_count` и `orders_per_zone_day` применяются только к неделе 1 (`fieldIdForPlan:1573–1581`), для недель 2–6 уходят в `skipped`.
**Следствие:** ИИ не может управлять объёмом и ТМЦ-целью, хотя промпт эти поля предлагает. Отсюда же растёт риск советов «нарастить объёмы» без рычага.

### Н-6. «MAPE» — не MAPE
`1732`: `|exp − fact| / max(1, |fact|)` — одноточечная ошибка; при отрицательной прибыли считается от модуля убытка и знак не различает (exp −200 000, fact −217 091 → «7.9%»), а `expected_delta_vs_baseline_pct` вообще не сверяется с фактом.

### Н-7. «Заполненность» в легенде = 100% при одних галочках
`calcQualityScore:394–416` считает среднее **только по введённым** полям; это уже зафиксировано тестом (`ds_selfcheck.cjs:105–110`) и пунктом TODO 0.1.

## 6. Тесты и критерии приёмки

**Тесты (добавить в `ds_selfcheck.cjs` / `ds_domcheck.cjs`):**
1. В форме недели 5 есть `exits5`; `metricSource(5,'exits') === 'entered'` после ввода.
2. Неделя с одним текстовым полем: `profitForWeek` → `null`, в отчёт не попадает, «Заполнено недель» её не считает.
3. Сводка содержит `calibration`, `loss_weights`, `breakeven_margin_rub`, `metric_source`, `loss_breakdown_rub_day`.
4. `Σ(loss_breakdown) == profit_rub_day` ±1 ₽ на трёх сценариях (здоровая экономика, убыточная, неделя с наследованием).
5. Гейт куратора при `curatorThreshold = 60` и кураторе 70% → `[OK]`.
6. Нет прогонов ИИ → `mape_pct === null` и `mape_status === 'not_applicable_no_ai_runs'`; ответ оценщика с `mape_pct: 0` отклоняется валидатором.
7. `validateEvaluation` принимает корректный `evaluation/2` и отклоняет ответ без `risk_scale`/`gaps_ranked`.
8. Старый ответ `strategy/1` по-прежнему принимается (обратная совместимость).

## 8. Риски

| Риск | Как снимаем |
|---|---|
| Отчёт разрастается и ИИ теряет фокус | Сводка остаётся машиночитаемой, прозой — только вердикт; в промпт уходит тот же JSON, что и в отчёт |
| Наследование метрик останется незамеченным | `metric_source` обязателен; недели без измеренных метрик выпадают из MAPE и гейтов |
| `null` в полях ломает старые прогоны | Валидатор нормализует `strategy/1` → `strategy/2`, старые `aiRuns` читаются как есть |
| ИИ снова назовёт «провал выходов» там, где данные не измерены | В промпте и отчёте явный блок «что измерено, что унаследовано, что дефолт» |
| Бенчмарки устарели/недоступны | `benchmark_status` и дата выгрузки; без источника — поле пустое, а не выдуманное число |

## 9. Что не делать

- Не считать MAPE и риск-скор по неделям с унаследованными метриками — получим «точность» на шуме.
- Не масштабировать объём, пока `contribution < 0`: при −47 ₽/заказ рост Q на 10% увеличивает убыток примерно на 6 200 ₽/день (при Q = 1320).
- Не поднимать `SCHEMA_VERSION` без миграции старых прогонов.
- Не добавлять бенчмарки «по памяти» — только с источником, датой и лицензией.
